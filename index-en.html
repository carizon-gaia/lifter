LiFTeR
Technical Overview

Conditioned on six camera views, a multi-view DiT generates a LiDAR latent in a joint latent space. A Gaussian decoder then predicts per-ray 2D Gaussians and renders range, intensity, and return attributes.

01 / OVERVIEWTHE IDEA

PROBLEM FORMULATION

From cross-modal generation
to renderable representations.

Goal: generate a scene representation with LiDAR geometry and return attributes conditioned on camera observations.

Per-scene reconstruction typically relies on real LiDAR and scene-specific optimization; direct point-cloud or range-map generation does not inherently provide a continuous scene representation. LiFTeR explores feed-forward Gaussian decoding after camera-conditioned generation, mapping latent representations to renderable per-ray Gaussians to reduce per-scene optimization and explore new scenes and poses.

The current code primarily covers six-camera conditioned diffusion and single-frame 2DGS rendering on nuScenes. Broader LiDAR conditioning, novel-pose simulation, and multi-frame capabilities are research goals or extensions, not features verified in the main CLI.

01 / REPRESENTATION

LiDAR range view

Arrange range, intensity, and return validity by beam and azimuth in a two-dimensional sensor-coordinate representation.

02 / GENERATION

Multi-view EDM

Learn a conditional distribution over LiDAR latents using camera conditioning, a multi-view DiT, and EDM noise scheduling.

03 / RENDERING

Per-ray 2DGS

Predict Gaussian geometry and sensor attributes from latents and differentiably render range, intensity, and raydrop.

02 / METHODHOW IT WORKS

TWO-STAGE FRAMEWORK

Cross-modal diffusion
and Gaussian decoding.

Stage I · Multi-view DiT
Stage II · Gaussian decoder

During training, frozen image and LiDAR VAEs encode camera images and range maps; their latents are aligned on a joint canvas. Stage I predicts a LiDAR latent by conditional diffusion. Stage II maps it to per-ray 2D Gaussians and renders them using sensor geometry. Direct VAE decoding is an alternative output path.

02 / STAGE I

Conditional diffusion and cross-view alignment

Freeze the tokenizers and train a multi-view diffusion transformer.

Conditioning and network

The LiDAR slot is the prediction target and the six camera slots provide conditioning. DiT uses 3D RoPE, learned view embeddings, and self-attention for cross-view interaction; the default pipeline does not rely on explicit camera-to-LiDAR pixel projection.

Training and sampling

Training samples noise levels and predicts clean latents; nuScenes separately normalizes the ground-truth LiDAR latent region and structural padding. Inference starts from Gaussian noise and uses iterative EDM/RES solving; the default is 2ab, 35 steps, followed by a final clean denoise.

Paper Figure 10 · Optional layout conditioning

The paper projects HD maps and 3D boxes onto the LiDAR ray grid and injects them into LiDAR tokens through residual adapters; 3D boxes are also encoded as cross-attention conditions. Layout conditioning requires appropriate data and configuration.

EDM FORWARD PROCESSxσ = x0 + σ ε   ·   ε ∼ N(0, I)

The model predicts x0 from the noise level and camera conditions; the implementation also uses EDM preconditioning and noise-weighted loss.

DiT is initialized from Cosmos Predict pretrained weights before camera-to-LiDAR training. The inference batch currently still reads and encodes LiDAR video to construct the canvas and evaluation data; the standard generation target is driven by noise rather than copying the ground-truth LiDAR latent. Camera-only deployment still requires adapting the data interface.

03 / STAGE II

Gaussian decoding and LiDAR rendering

The following describes the nuScenes V13 single-frame 2DGS path.

Latent → Gaussian attributes

Input [B, 16, 1, 8, 256]is converted into 512 tokens via 2×2 patches; a 16-layer backbone combines bidirectional Mamba-2 and transformers before upsampling to a 32×1024 beam grid.

Beam → observable return

Each beam predicts 12 values: depth, four attributes, two tangential scales, a quaternion, and opacity. Fixed normal thickness fits the 2DGS interface; raydrop probabilities yield sparse returns after rendering, and beam directions back-project the point cloud.

Each beam yields one 2D Gaussian: depth, four direct attributes, two tangential scales, a quaternion, and opacity. Multi-frame time and pose conditioning are not part of this single-frame diagram.

PER-RAY GEOMETRYμ = oray + d · rray

The Gaussian center lies on its corresponding beam;oray is the ray origin,rray is the unit direction, andd is the predicted distance.

Training freezes DiT and VAE by default and trains only the Gaussian head. Without a cache, training uses a single-step denoised latent; inference uses a multi-step sampled latent. Supervision includes range, intensity, raydrop, and geometric terms; ground-truth return masks and neighborhood-filled masks must be distinguished.

INFERENCE / INPUT MODALITIES

Inference: two input paths

Distinguishing the current interface from research extensions.

A / CAMERA-TO-LIDAR

Camera-conditioned generation

6 × RGB→RGB VAE→DiT multi-step sampling→LiDAR latent→Gaussian decoding / rendering

Standard current pipeline; the data interface still requires LiDAR fields to construct the canvas and evaluation data. Optional layout conditioning depends on the dataset and configuration.

B / LIDAR-CONDITIONED

LiDAR-input reconstruction

LiDAR range→LiDAR VAE→LiDAR latent→Gaussian decoding / rendering

Non-cross-modal research path; clean-latent training and diagnostic code exists, but this does not establish a standalone LiDAR-input inference entry point in the main CLI.

IMPLEMENTATION BOUNDARY

Multi-frame V13.1 predicts a target view using cached neighboring latents, time, and relative pose; default frame weights and main CLI integration still require verification. The V13.2 world-scene configuration is not registered. Arbitrary novel-pose simulation should not be treated as verified in the current single-frame path.

TECHNICAL FAQ

Design choices

Why not predict camera depth alone?

LiDAR observations include not only geometric range but also intensity, return probability, and sparse beam-sampled returns. Camera depth alone does not automatically provide these attributes; other methods may add modules to adapt them.

Why use 2D Gaussians?

The approach uses 2DGS for local surface representation and GS-LiDAR to render per-beam results. Effectiveness depends on data, parameterization, and comparison settings; it should not be assumed superior to 3DGS for all tasks.

Why decode Gaussians in latent space?

Compression reduces spatial positions, helping reduce sequence length, computation, and memory requirements; generation quality and efficiency still require validation with actual models, hardware, and experiments.

Why condition on cameras rather than occupancy?

Camera observations are more commonly available. This does not make occupancy invalid; different conditioning inputs have different data, geometry, and deployment requirements.

What remains unresolved?

Temporal and novel-view consistency, cross-modal inference efficiency, camera-only data interfaces, and sensor calibration and evaluation protocols remain to be verified. The 200 m range in project materials does not apply to the 50 m nuScenes configuration on this page.
